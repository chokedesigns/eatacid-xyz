`PHASE_3_RERUN`

Use only the required inputs for the declared mode. Do not inspect the repository or use conversational memory, assumptions, or outside facts.


RULES

1. Create one pre-Phase-3 trace record for every applicable Phase-2 finding, including preserved historically invalidated or otherwise non-active findings required by the Phase-3 contract.
2. Map each Finding ID to its checklist ticket(s) and then to actual landed commit/change provenance supported by `remediation-git-log.txt`. Preserve every supplied full commit hash and all many-to-one and one-to-many mappings explicitly. For each remediation commit, an exact supplied checklist Ticket ID in that commit's summary may serve as explicit commit-to-ticket association evidence when it resolves to the checklist ticket and its source mappings. An exact Ticket ID in a branch decoration may corroborate branch association but does not replace the required per-commit summary association.
3. Reconcile every full-hash in-scope log entry to at least one Finding ID or label it as non-finding repository change provenance only when supplied evidence supports that label. In the scoped PHASE_3_RERUN diagnostic route, use that label only from the declared current supplement after individual admission and independent consumer validation under Diagnostic Evidence Admission v1. Retain the original unmatched ticket/finding association as UNTRACED, prior classifications and historical unresolved references. Rejected/material unresolved records retain UNTRACED/INCOMPLETE effects. Preserve already supported derived-work accounting; diagnostic admission never supplies a formal ticket or finding relationship.
4. Carry forward Phase-2 dispositions, affected objects/domains, discovery identity and rows, acceptance criteria, verification targets, external/manual dependencies, residual risk, and source references without reinterpretation.
5. A completed checklist item or landed commit is not verification and is not closure. Record verification as passed only when the supplied evidence explicitly demonstrates the supplied acceptance criteria were satisfied.
6. Never invent a ticket mapping, commit/change provenance, verification result, source reference, or relationship. Names, chronology, topical similarity, or apparent intent without an exact source checklist Ticket ID are not mapping proof.
7. Use `UNTRACED` for missing required evidence or provenance and `NONE` only for an evidenced absence. Use `UNKNOWN` for remediation status when the supplied evidence cannot establish another allowed status. Use `NOT_RUN` only when supplied evidence establishes that verification was not run; otherwise use the Phase-3 contract's applicable `FAILED`, `PASSED`, `EXTERNAL_REQUIRED`, or `UNVERIFIABLE` value.
8. Missing required provenance must remain visibly `UNTRACED`; do not repair it with inference or describe the trace as complete/resolved.
9. Do not perform a new audit, invent findings or work, modify finding dispositions, or assert any closure, stopping-boundary, or gate result.
10. Do not fabricate or pre-populate Phase-3-owned rerun obligation IDs, rerun row references, Phase-3 verification evidence, final Finding Schema dispositions, or stopping-boundary effects. Phase 3 adds those fields from its actual rerun.


PHASE_3_RERUN MODE

1. Preserve every existing Phase-2 trace identity, record, mapping, and historical reference. Update a record only with supplied later evidence; never replace or drop its history.
2. Include every finding first discovered by the latest prior `P3-L1-CLOSURE-v1` that now requires remediation-trace coverage under the Phase-3 prompt's prior-attempt rules.
3. Preserve every prior Phase-3 Finding ID, discovery Audit-run ID, discovery row reference, disposition, source reference, and prior trace identity when one already exists. If no trace identity exists, assign a new stable Trace ID without inventing provenance.
4. Map each prior-Phase-3-originated finding through the updated checklist ticket(s) to actual landed commit/change provenance using the same evidence rules as Phase-2 findings.
5. Never drop finding or trace history from an earlier Phase-3 attempt, even when a later artifact supersedes its current result.
6. For a finding first discovered in Phase 3, use evidenced `NONE` for Phase-2-only identity fields and carry its actual prior-Phase-3 discovery identity, disposition, and row references in `Source references`. Use `UNTRACED` instead if the supplied prior Phase-3 artifact does not establish the required ancestry.
7. Do not copy prior Phase-3-owned rerun rows, verification evidence, final dispositions, or stopping-boundary effects into the new rerun's Phase-3-owned fields. Preserve them only as historical source references; the next Phase-3 rerun must populate its own fields.
