# AGENTS.md — eatacid-xyz (frontend + shared + nested admin-ui workspace)

## Prime directive
- Preserve 100% of existing behavior unless the ticket explicitly requests a behavior change.
- Prefer the smallest diff that satisfies the ticket.

## Scope control
- Only touch files required for the current ticket.
- No drive-by cleanup: no formatting sweeps, renames, reorganizations, or “while we’re here” changes.

## Repo boundaries (VERY IMPORTANT)
- This workspace contains two git repos: the outer repo and the nested admin-ui repo.
- If edits span both repos, keep changes logically separated and report:
  - which files changed in which repo
  - recommended commit grouping (per repo)

## Webflow / DOM contract
- Do not rename/remove DOM ids/classes/data-attrs used as JS hooks unless explicitly requested.
- Do not change Webflow-ripped HTML structure unless explicitly requested.

## Drop params rules (shared + admin-ui mirror)
- `shared/drop-params/drop-params.js` is source-of-truth.
- The drop-params watcher intentionally watches only `shared/drop-params/drop-params.js`; edits outside that file are not part of the supported regeneration flow unless watcher coverage is explicitly expanded later.
- `shared/drop-params/drop-params.json` is generated.
- `admin-ui/src/drop-params.mirror.json` is generated by the watcher.
- Keep mirror-specific metadata narrow. If admin-ui needs an authoritative mirror network assumption, store it explicitly in `shared/drop-params/drop-params.js` as a small field instead of inferring it from `dropName`.
- Do NOT edit generated JSON files by hand.
- Do NOT change the schema/keys of drop params unless explicitly requested.

## Network rules
- Do not enable mainnet or change address blocks unless explicitly requested.
- Remember: your app’s `testnet` corresponds to Beacon `ghostnet`.

## Error handling + logging
- No silent failures in logic paths.
- `catch {}` allowed only for optional cleanup (removeListener/detach).
- Avoid adding always-on console noise; gate debug logging behind an explicit flag.

## Verification requirements (must include in completion message)
Always end with:
1) Summary
2) Files changed (grouped by repo)
3) Verification steps (exact commands + manual checks)
4) Rollback note (what to revert)

## Patch artifact requirement (must include in completion workflow)
Before writing the completion message, export a diff artifact that includes new/untracked files.

In the repo you modified (outer repo or nested admin-ui):
1) Run: `npm run ticket:diff`
2) Confirm it created (overwrite OK):
   - `ticket.<branch>.diff`
   - `ticket.<branch>.stat.txt`

Notes:
- This overwrites the same files each run; on fix passes, re-run it.
- Always run `git rev-parse --show-toplevel` first to confirm you are in the correct repo before exporting.

## Allowed commands (workspace)
- Prefer using existing npm scripts only.
- Outer repo useful scripts:
  - `npm run start`
  - `npm run build:pages:staging`
  - `npm run pages:sanity`
  - `npm run ticket:diff`

- Nested admin-ui useful scripts (run from /admin-ui):
  - `npm run dev`
  - `npm run build:clean`
  - `npm run ticket:diff`
